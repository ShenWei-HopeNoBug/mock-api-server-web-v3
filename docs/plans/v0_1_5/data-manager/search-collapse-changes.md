# outputManager 搜索区自动收起可选化变更

> 状态：已实施
> 范围：本仓 `apps/dataManager/views/outputManager/index.vue`
> 前置方案：[search-collapse-plan](search-collapse-plan.md)

## 1. 背景

`search-collapse-plan` 落地后，查询/重置提交即自动收起筛选浮层。「连续调整筛选条件多次查询」场景下每次都要重新点开浮层，操作路径冗长。

## 2. 目标

浮层顶部新增勾选项控制「查询后自动收起」，默认勾选（保持现状行为）；取消勾选后查询/重置保持浮层展开，便于连续调参查询。

## 3. 改动清单

| #   | 位置   | 改动                                                                                | 说明                                                                                                              |
| --- | ------ | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 1   | 模板   | `.search-area` 顶部新增 `.search-options` 行：右对齐 `a-checkbox`「查询后自动收起」 | 右对齐与 `.tool-bar` 按钮列同侧；字面中文与页面既有文案风格一致（`SearchForm` 走 i18n 因其为共享组件）            |
| 2   | script | `autoCollapseAfterSearch = ref(true)`；`onSearchSubmit` 收起动作加条件门控          | `SearchForm` 的「重置」内部走 `reset() → onSearch() → emit('submit')`，与「查询」同一 submit 出口，一处门控全覆盖 |
| 3   | style  | `.search-options` `display:flex; justify-content:flex-end; margin-bottom:8px`       | 浮层内薄选项行                                                                                                    |

## 4. 不改动的部分

- `SearchForm` 共享组件：零改动（勾选态由页面侧持有）
- 筛选 toggle 手动展开/收起、`activeFilterCount` 徽标、批量删除：行为不变
- 持久化：不引入（localStorage 项目无先例，内存态够用；如需跨会话记忆另行评估）

## 5. 影响面

| 项       | 评估                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 文件     | 1 代码文件                                                              |
| 行为变化 | 新增可选开关，默认勾选 = 现状行为，无感知升级；取消勾选后 submit 不收起 |
| 风险     | 低，纯展示层；`a-checkbox` 走自动按需引入                               |

## 6. 验收

- `lint:check`/`format:check`/`build` 过
- dev 目检：浮层顶部见「查询后自动收起」勾选框（默认勾选）→ 取消勾选后点查询/重置，浮层保持展开 → 勾选后恢复自动收起
